# OTC 衍生品语义导航 V2 提案

## 这次要审什么

请审阅“导航怎么组织”和“字段语义怎么挂载”，不是审阅代码，也不是逐个确认 1375 个概念。

核心判断是：这棵树是否应该作为字段语义地图的全局导航骨架。

## proposed 导航骨架

1. 参与主体：客户、交易对手、机构、交易员，以及买方/卖方等角色
2. 产品与标的：产品、标的、产品类型、市场对象
3. 询价、订单与交易：询价、报价、订单、成交、交易
4. 合同与结构：合约、方案、组合、合约腿
5. 合同生命周期：建立、生效、重置、平仓、终止
6. 持仓与风险：持仓、头寸、多空方向、对冲、限额、准入
7. 估值与履约保障：名义本金、估值、保证金、抵押品、费用、利息
8. 执行、清算与结算：市场成交、清算、交割、现金流、结算结果
9. 参考数据与配置：币种、市场、交易所、规则、参数
10. 运营、报表与数据加工：批处理、报表、对账、数据加工、运行状态

这 10 个一级区域是开放配置，不代表当前数据库已经覆盖全部区域。

## 字段不再直接塞进一棵分类树

以“名义本金”为例，预期投影是：

```text
名义本金                         业务概念
├─ 初始名义本金                  属性表达
├─ 动态名义本金                  属性表达
├─ 多头动态名义本金              属性表达 + 方向限定
├─ 调整后动态名义本金            属性表达 + 状态/调整限定
│
├─ 标识 / 金额 / 币种 / 时点      可复用字段属性与限定轴
│
└─ Schema / Table / Column       物理实现
```

其中“金额”不是另一个业务概念；“动态”也不是简单的字段后缀分类，而是属性表达或限定维度，必须由字段注释、结构或其他证据支撑。

## 当前试做暴露的问题

在 TRADEFLOW 的 1375 个业务概念上，当前配置只产生：

- 12 个单区域候选
- 1 个跨区域冲突
- 1362 个未知概念

这不是说业务只有 13 个概念，而是当前方法选择了“证据不足就保留 UNKNOWN”，没有把剩余概念硬塞进某个一级菜单。

## 需要你判断的 4 件事

### 1. 一级业务骨架是否合理

上述 10 个区域是否足以作为 OTC 衍生品语义导航的第一层？是否有应该合并、拆开、改名或补充的区域？

### 2. 分层方式是否合理

是否同意把“业务概念、属性表达、字段属性/限定、物理实现”拆成不同投影，而不是全部变成树节点？

### 3. UNKNOWN 的处理是否合理

是否同意未知概念先进入可解释的待确认队列，而不是根据名称猜测归类？

### 4. 是否允许替换现有字段语义地图入口

只有前三项认可后，才进入现有页面替换；本提案不把当前试做结果直接当成业务结论。

## 建议审阅结论

请给出以下三种结论之一：

- `ACCEPT`：骨架和分层可以进入页面试做
- `REWORK`：方向认可，但指出需要调整的区域或边界
- `STOP`：不采用这套导航抽象

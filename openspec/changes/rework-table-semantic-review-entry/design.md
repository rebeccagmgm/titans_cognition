## Context

现有生成器已经输出 477 个 `table_profile`、候选、Assertion、Evidence、字段辅助摘要、表组、关系和五张调查卡。页面也已经使用稳定 `asset_id` 和静态分片，但默认布局把 2 个业务协作组与 5 张调查卡放在主导航中，表目录首批仅有 100 张且没有加载范围提示，详情主要呈现原始 JSON。参见 proposal.md 的动机与增量 spec 的读者行为要求。

本 Change 只修改 Gate 通过后的静态审阅 Projection。Canonical 结果、候选生成、关系 Gate、固定测试聚合和字段侧运行均保持不变。

## Goals / Non-Goals

**Goals:**

- 复用字段版已经验证的阅读节奏：先看语义导航和数量，再看矩阵，最后看具体实例与证据。
- 保证全量范围、当前范围、加载状态和筛选状态始终可见。
- 让表级候选、字段辅助、反证和 Unknown 围绕具体 Assertion 组织，而不是展示成无解释的原始对象堆叠。
- 将调查卡和结构线索保留为专项复核工具，同时消除其代表全量分类的视觉错觉。

**Non-Goals:**

- 不设计一套固定、唯一或跨 Schema 通用的表分类本体。
- 不新增或修改表职责、上下文、锚点、表组、关系和字段语义的推理规则。
- 不补采 Wiki 正文、业务数据行或新的测试聚合，不启用 LLM。
- 不在本 Change 中写入人工 Review Decision 或宣告业务验收。

## Decisions

### 1. 借用字段版的信息架构，不继承字段版的语义模型

默认页采用四段式：顶部全貌条、左侧浅层语义导航、中间全量表矩阵、右侧单表画像。导航只展示当前运行真实存在的业务上下文、业务锚点和推荐/发现职责，并显示每个值覆盖的唯一表数。页面文案明确“树用于浏览，候选可多值”。

替代方案是把表强制放进 `产品 → 对象 → 生命周期` 唯一树。该方案更像传统目录，但现有证据不能保证 477 张表都具有唯一上位归属，会把示例词表固化成事实，因此不采用。

### 2. 由生成器计算可复核统计和轻量表行

生成阶段从现有数据集计算：全量总数、处置分布、候选覆盖、Unknown/Conflict、字段辅助状态、Review Decision 状态以及各导航值的唯一 `asset_id` 数。统计同时携带口径类型（互斥分布、可重叠标签、状态）。每个表行预先加入候选值摘要和字段辅助状态，页面无需扫描 7MB 详情对象才能绘制矩阵。

不由前端临时猜测统计口径，也不引入新的统计数据集；所有值都来自本次已固定的 Projection 输入。

### 3. 明确区分数据加载范围和筛选范围

静态页面保留分片加载，但增加 `已加载 X / 总计 Y`、失败分片和“当前结果 A / 全量 Y”。在全部分片加载完成前，页面不得显示“全部”或把当前行数当作总量。搜索、候选导航和状态筛选统一写入一个可见的当前范围条；清除入口同时清除搜索、筛选和专项范围。

加载失败时保留已经加载的行，但把页面状态标为不完整并列出失败分片。这样既不阻塞静态首屏，也不制造完整性错觉。

### 4. 默认主体地图、完整物理清单与专项复核分区

默认区域只有全貌、语义导航、表矩阵和单表画像，表矩阵初始范围取 Canonical `disposition=SUBJECT`，当前固定运行为 233 张。其余 244 张后缀表继续保留在完整物理清单，并通过“后缀/变体或其他处置”专项折叠入口访问。前端不重新用数字正则判定备份或停用；`LIKELY_VARIANT / UNKNOWN / STANDALONE` 继续按 Canonical 处置显示。

业务协作组、调查卡、物理变体组和结构邻域同样放入独立的“专项复核”页签或折叠区域，每个入口显示类型、成员数、候选/未决状态和用途说明。进入任何专项范围后仍复用同一表矩阵和 `asset_id` 详情，并保留“返回主体表”和“查看全部物理表”入口。

不删除五张调查卡，因为它们仍是模型 Gate 和反例复核的重要工程资产；只改变其读者位置与文案。

### 5. 单表详情以 Assertion 为主线组织

详情顶部先给表名、注释、物理处置和边界；随后按上下文、锚点、职责和关系列出候选。每项候选显示状态、方法、直接 Evidence、Counterevidence、字段作用和 Review Decision。字段辅助按 `SUPPORT / DISTINGUISH / COUNTER / NOT_USED` 呈现，原始字段摘要和方法分数放入折叠技术详情。

现有对象没有对应 Assertion 或字段关联时显示 Unknown/未使用，不通过前端推导补齐。Panorama Object Card 继续作为物理事实入口。原始 `profile` 与 `field_support` JSON 只作为默认收起的审计与调试数据保留，普通读者不需要通过它理解业务语义。

### 6. 以真实读者任务验证页面，而不只检查 HTML 字符串

单元测试验证统计口径、唯一表计数、轻量行摘要和缺失/冲突状态。页面测试至少执行以下真实交互：首次看到 477 总量与加载状态、选择候选后看到当前/全量数量、清除后恢复全量、打开专项卡看到成员数但不丢失全量入口、打开含字段辅助与反证的表并定位具体 Assertion、模拟分片失败看到不完整状态。

静态字符串断言只用于固定边界文案，不能单独完成读者入口验收。

## Risks / Trade-offs

- [多个统计轴彼此重叠，容易再次被理解为互斥分类] → 每组统计携带口径标签；不使用饼图或总和暗示，只在真正互斥时展示分布。
- [候选值较多导致左侧导航拥挤] → 默认只显示有覆盖的值、唯一表数和可展开列表；搜索仍以全量表矩阵为权威入口。
- [详情数据较大，首次载入可能变慢] → Catalog 只保留轻量行和统计；详细 Evidence 继续独立加载，未来可按 `asset_id` 分片，但本 Change 不扩大为新的存储层。
- [页面更易读后，候选可能被误认为正式标签] → 候选、Unknown、Conflict、人工决定和业务验收状态在总览与详情重复显示，不使用“已分类”“准确率”等措辞。
- [字段侧并行 Change 可能导致输入 Manifest 漂移] → 不修改字段输出；重跑前只接受配置锁定的字段输入，漂移时按现有规则标为 `NOT_EVALUABLE` 并在页面显示。

## Migration Plan

1. 先为现有 477 张表结果增加读者统计和轻量矩阵数据，保持旧 Canonical 文件不变。
2. 替换 `review/index.html` 的默认信息架构，并保留稳定 hash/`asset_id` 深链。
3. 运行聚焦测试和真实静态页面交互验证，再对生成产物执行代理读者评审。
4. 评审通过后重生成现有 stage4 输出；若失败，回滚生成器和审阅目录即可，Canonical 表语义结果无需回滚。

## Why

现有表语义审阅页已经生成 477 张表的画像与证据，但主入口以协作组和调查卡为中心，缺少全貌统计、当前范围计数和稳定的逐层阅读路径，导致方法验证样例被误解为全量分类结果。现在需要在不扩大推理范围、不改变 Canonical 候选的前提下，把现有工程结果重组为可理解、可复核的表知识入口。

## What Changes

- 将表审阅页重组为“全貌统计 → 表语义导航 → 全量表矩阵 → 单表画像与证据”的主阅读路径。
- 首页明确显示总表数、当前筛选数、主体/变体或其他处置、候选覆盖、Unknown、Conflict、字段辅助使用和人工审阅状态；互相重叠的统计不得伪装成可相加分类。
- 采用“浅层浏览 Projection + 多维候选切面”，不建立唯一或封闭的多级业务分类树；所有入口值从当前运行的候选和状态派生。
- 让全部 477 张表在目录中可达，提供明确的加载、分页、筛选范围与清除状态，避免首批分片或调查卡过滤被误认为全量。
- 单表画像逐条展示业务上下文、业务锚点、职责、关系、字段支持/区分/反证、Unknown 和证据边界；字段只能解释具体表级 Assertion，不能汇总投票。
- 将业务协作组、调查卡、物理变体和结构邻域移入独立的“专项复核”区域，并明确它们分别是候选业务关系、方法验证样例或结构线索，不再作为默认全量目录。
- 保持现有表画像、候选、Assertion、Evidence、Counterevidence、Review Decision 和 `asset_id` 不变；本 Change 不新增业务行查询、Wiki正文获取、模型调用或正式业务标签。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `table-semantic-map`: 修改表语义审阅 Projection 的读者入口、全量统计、导航/切面、表矩阵、单表证据呈现与专项复核边界要求。

## Impact

- 主要影响 `src/titans_cognition/table_review.py`、表审阅页面测试、表语义地图增量规范与生成的静态审阅产物。
- 不改变表语义 Canonical 数据集、表级推理规则、固定输入配置、数据库访问边界或字段语义输出。
- 现有本地审阅页布局会被替换，但其表详情定位和稳定 `asset_id` 继续兼容。

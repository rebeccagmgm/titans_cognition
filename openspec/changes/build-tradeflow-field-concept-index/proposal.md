## Why

现有 Panorama 能从表查看字段，却不能从“金额—名义本金—初始名义本金”等多粒度概念反向找到字段和所在表。字段名、中文注释、类型和表上下文已经足以先做一个轻量字段概念索引，验证这种导航是否比孤立字段清单更有用。

## What Changes

- 建立配置驱动的字段概念发现引擎，不把算法硬编码到某个 Schema；首次验证固定使用 `TITANS_TRADEFLOW` 数字后缀过滤后的 233 张表，其他范围须另行配置和验证。
- 将字段名、中文字段注释、声明类型和少量表上下文组合为字段表示；任一信号缺失只降低该视角可用性，不使字段不可用。
- 使用成熟的文本检索与聚类路线：名称/注释规范化、字符 n-gram 与 TF-IDF 相似、类型兼容特征、有界近邻召回和层次聚类；不依据单一同名或同注释自动判定业务等价。
- 输出三级概念结构：通用数据类别、基础业务概念、限定业务概念。例如 `金额 → 名义本金 → 初始名义本金`；字段关联最具体概念，搜索父概念时自动包含后代字段。
- 同名异义、异名同义和注释差异通过综合相似与表上下文形成候选；低于阈值或存在竞争的字段允许不分配或保留多个候选。
- 正式结果收缩为 `concepts.jsonl`、`field_concept_links.jsonl` 和 `manifest.json`，复用现有 Physical Facts，不复制字段事实；相似边和聚类明细只作为可选诊断输出。
- 生成一个最小审阅页面，支持概念到字段/表、字段到概念的双向查看；首先审阅“名义本金”及相邻概念，再决定是否继续调整或扩大范围。
- LLM 不是必需依赖；第一版不用外部 LLM 判断每个字段。未来如启用，只辅助候选簇命名或父子关系建议，并继续受 D-005 控制。
- 明确不读取列值、不建立正式业务本体或标准字段、不引入图数据库/向量数据库、不宣称跨 Schema 泛化，也不在本 Change 内完成正式 Panorama 页面整合。

## Capabilities

### New Capabilities

- `tradeflow-field-concept-index`: 定义一个配置驱动的轻量字段概念引擎及其 TRADEFLOW 233 表首轮验证，包括三级概念树、字段链接、最小结果文件和审阅行为。

### Modified Capabilities

- `cognition-delivery-governance`: 授权一次以 TRADEFLOW 233 表为验证范围的字段概念候选试验，同时继续禁止正式本体、跨 Schema 泛化、业务验收替代和自动规模化。

## Impact

- 复用现有 Physical Facts、Manifest、JSON/Parquet 工具和静态 HTML；新增一个独立字段概念模块、CLI 命令、轻量配置、测试和审阅 Projection。
- 第一版优先使用成熟本地算法库或等价的确定性实现，不新增远程服务；如引入新的 Python 依赖，必须锁定版本并验证 Windows 可运行性。
- 历史 Panorama、表级分类和 V1B 结果不原地修改；运行结果默认只保存在本地并保持 Git 忽略。

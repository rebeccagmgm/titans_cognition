## Context

现有 Physical Facts 已保存字段名、中文注释、类型和所属表；表级分类原型也表明通用字段容易造成过宽社区。当前目标不是构建严谨本体，而是快速验证多粒度字段导航是否有实际增量，因此需要采用成熟的文本表示与层次聚类，并把正式输出压缩到用户真正会查询的概念树和字段链接。

## Goals / Non-Goals

**Goals:**

- 以配置驱动的同一引擎处理明确指定的字段范围，TRADEFLOW 233 表仅是首轮配置。
- 形成 `通用类别 → 基础概念 → 限定概念` 的三级树及字段链接。
- 用少量、成熟、可解释的本地算法快速跑出可审阅结果。
- 审阅页的 DOM 规模必须由分页上限决定，而不是随 Schema、概念或字段总量线性增长。

**Non-Goals:**

- 不追求一次判断所有字段的精确业务语义。
- 不保存用户无需理解的大量中间证据表。
- 不构建跨 Schema 概念合并、本体治理或标准字段平台。

## Decisions

### 1. 引擎通用、运行有界

新增独立字段概念模块和命令，读取 `facts/objects.json`、`facts/columns.json` 及范围配置。配置负责选择 Schema、对象类型、排除规则和预期数量；算法只处理选中的字段，不出现 TRADEFLOW 专属分支。

首轮配置固定当前 TRADEFLOW Physical Facts 和数字后缀过滤结果，验证 233 张表。后续 Schema 只可通过新配置试跑，不能自动与现有概念树合并。

### 2. 每个字段只有一条组合文本表示

字段表示保持简单：

```text
英文名称 Token + 中文注释 + 类型族 + 表名/表注释的低权重上下文
```

英文名进行 snake/camel/数字边界切分和常见缩写归一；中文只做 Unicode、标点、空白和少量通用词处理。缺少注释时其权重为零，字段继续参与。表上下文权重低于字段自身文本，防止把整张表的主题强加给每个字段。

### 3. 使用 TF-IDF、字符 n-gram 和余弦近邻作为第一版主算法

字符 n-gram 同时适合中文短注释、英文缩写和拼写变体；TF-IDF 能降低“ID、状态、金额”等高频词影响。名称、注释和上下文可分别向量化后按固定权重组合，类型兼容作为附加特征而非普遍硬否决。

候选生成只保留每个字段 Top-K 和最低相似阈值。第一版优先使用经过版本锁定的成熟本地实现；如果环境没有合适依赖，再用小型确定性实现完成相同契约，不引入远程向量服务。

**拒绝纯 Embedding/LLM 路线：** 内部缩写和短字段缺少可靠通用语义，且会增加模型、外发和可重放成本。

### 4. 使用层次聚类生成多粒度结构

在稀疏近邻候选内使用 agglomerative hierarchical clustering。较松阈值形成通用类别或基础概念，较严阈值形成限定概念；低于分配阈值的字段保持未分配。聚类不使用连通分量闭包，避免 A≈B、B≈C 导致 A 与 C 被无条件合并。

概念层级最多三级：

```text
L1 通用数据类别：金额
L2 基础业务概念：名义本金
L3 限定业务概念：初始名义本金
```

聚类先产生候选组，再用组内高频中文短语、英文 Token 和父组差异生成确定性候选标签。无法形成受支持簇的字段保持未分配，不调用 LLM 强行命名。

### 5. 同名和同注释都只是特征

- 同名、同注释：高相似候选，但表上下文明显不同时可以分开。
- 同名、不同注释：可能是同名异义，也可能是同一基础概念的不同限定子概念。
- 异名、同注释：可能是别名，也可能是注释过宽；由组合相似决定。
- 异名、近似注释：通过字符 n-gram 和上下文召回。

不再建立“精确语义等价组”。完全一致只影响分数，不自动产生业务等价声明。

### 6. 正式只保存概念和链接

```text
field-concepts/
├─ concepts.jsonl
├─ field_concept_links.jsonl
├─ manifest.json
└─ review/index.html
```

`concepts.jsonl` 保存 `concept_id`、`label`、`level`、`parent_id` 和成员数量；`field_concept_links.jsonl` 保存 `field_id`、最具体 `concept_id`、方法分数和 `CANDIDATE/AMBIGUOUS`。未分配字段可从 Physical Facts 与链接差集得到，审阅页直接显示数量。

调试时可以选择输出 `diagnostics.jsonl`，包含 Top-K 邻居和聚类信息；它不是正式数据契约，也不进入导航依赖。

审阅 HTML 仅嵌入紧凑的概念与字段数据，不预渲染全量树和字段表格。主线程每次最多渲染固定数量的概念与字段；字段反查由 Web Worker 扫描内存索引并分页返回，使未来扩大到多 Schema 时页面交互不会被全量 DOM 阻塞。

### 7. 先看名义本金，再决定是否继续

完整算法可以处理 233 张表的全部字段，但首轮验收只聚焦：

- `金额 → 名义本金 → 初始/当前/动态/剩余名义本金` 是否形成；
- 相似字段是否分布到合理的物理表；
- `AMOUNT/金额` 是否出现明显跨业务误并；
- 没有足够信息的字段是否保持未分配。

若这组可见结果没有增量价值，停止调参和扩大范围；不增加复杂 Evidence 层或大批 LLM 调用挽救方案。

## Risks / Trade-offs

- [层次聚类不等于真实业务层级] → 明确标为候选树，首轮只判断导航是否有用。
- [概念标签可能不稳定] → 使用配置哈希和方法版本；人工修正先保存为简单覆盖配置，不建设审核平台。
- [通用词造成大簇] → TF-IDF 降权、Top-K、层级阈值和低权重表上下文共同限制。
- [没有列值导致部分歧义无法解决] → 允许多候选和未分配，不把覆盖率作为成功条件。
- [通用算法未经第二 Schema 验证] → 代码保持配置驱动，但只声明 TRADEFLOW 首轮结果。

## Migration Plan

1. 增加轻量范围配置和输出契约测试。
2. 实现字段表示、TF-IDF/字符 n-gram 近邻和层次聚类。
3. 对 TRADEFLOW 233 张表运行一次，生成三个正式结果文件和审阅页。
4. 只审阅“名义本金”与明显误并；根据可见结果决定继续、调小范围或停止。

回滚时忽略或删除本次生成的独立输出目录；上游 Physical Facts 和历史页面不受影响。

## Context

前一个 Change 已建立以 `dimension-details.jsonl` 为主表的标签维度静态投影，但完整的 SZData 标签快照还提供 `tag-values.jsonl`、`tag-dimensions.jsonl` 及关联记录。真实全量抓取显示标签列表源端总数为 17,969，而旧 OpenCLI 仅落盘 10,000 条并误报 `COMPLETE`；续跑还会丢失关系专属维度详情以及把累计详情数写成本轮新增数。本 Change 因此同时修正只读快照契约和 Cognition 阅读投影。

## Goals / Non-Goals

**Goals:**

- 建立明确的 tag value、tag dimension 和 relation 三类输入模型。
- 在一个快照绑定的页面中提供统一目录树，并保留对象类型与双向关联证据。
- 对 dimension-only、all-scope、部分关联和失败输入保持可见的证据状态。
- 保持旧的维度目录、SQL 原文、格式化 SQL 和高亮能力可用。
- 保证全量快照的分片总数守恒、唯一记录数与源端期望数一致，并在续跑后保持累计 manifest 一致。

**Non-Goals:**

- 不修改平台接口、不写平台，也不把源端无目录配置推断成业务目录。
- 不采集或展示业务标签值行，不执行 SQL，不验证标签实际生效。
- 不把目录字段提升为业务分类结论，也不建立通用元数据平台。

## Decisions

1. **双对象数据模型。** 标签值以 `tagId` 为主键，标签维度以 `tagDimId` 为主键，关联以 `(tagId, tagDimId)` 为复合键；这样避免把两个截图中的管理对象压成一张表。

2. **兼容输入而非隐式补全。** 完整输入优先消费快照里的标签值和关联文件；旧维度快照仍可生成维度视图，但标签管理区显示未采集。不能从 SQL、标签名或维度名补写关联。

3. **统一阅读树、对象级隔离。** 页面按“类型 → 目录 → 标签维度 → 标签”组织阅读；维度作为可选择的分组节点，标签作为叶子。两类节点使用不同标识、边框和底色，详情仍按对象类型渲染，底层 `tagDimId`、`tagId` 和多对多关系保持独立。一个标签关联多个维度时允许出现多个导航入口，但总量按唯一 `tagId` 统计。

4. **失败状态原样保留。** 输入校验失败采用原子发布；关系查询的 `FOUND`、`PARTIAL`、`COMMAND_EXEC` 等状态保留在关联记录上，并在页面明确显示。

5. **修正 OpenCLI 完整性契约。** 真实 all-scope 抓取已证明普通页码在 10,000 条处形成结果窗口。适配器按页面已支持的 `tagType`、`status`、`isCompoundLabels` 逐级动态分片，只有子分片总数之和严格等于父分片总数才继续；任一分片仍超窗、总数不守恒或唯一抓取数不足时，状态必须为 `PARTIAL`。

6. **续跑从落盘证据恢复。** 续跑除恢复页进度和对象 ID 外，还从关系文件恢复待补详情的维度 ID；manifest 使用累计唯一记录数，空页不得覆盖已知总数。源端总数发生变化时保留漂移状态，干净交付使用新目录重抓。

7. **类型与目录正交。** `tagType/tagClas` 表示平台的“持仓/组合”类型，不是目录字段。阅读树先按该类型分层，再展示平台目录或目录证据缺口；源 mapper 统一把代码 `1/2` 翻译为“持仓/组合”，投影同时兼容修复前快照中的代码字段。

8. **任务字段采用非空证据优先。** 维度详情接口的空任务数组不能证明“未配置”，因为真实管理列表会单独返回 `markingTask/newTagingTask`。新快照在 mapper 层以详情非空值优先、列表非空值补充，并按 `taskId` 稳定去重；续跑先从已落盘列表恢复内存映射；阅读投影对修复前快照执行同样的只读兼容，不改写源文件。

## Risks / Trade-offs

- [Risk] 标签值与维度关联文件命名或字段版本存在差异 → Mitigation：建立候选文件优先级和字段别名校验，记录实际采用的输入文件，不静默猜测。
- [Risk] 全量标签数据使静态页面变大 → Mitigation：先采用当前快照级页面并测量文件大小；只有读者验证性能不足时再设计分片。
- [Risk] 关系失败被读者误解为没有关联 → Mitigation：把失败状态、关系覆盖数和未采集说明放进摘要与详情。
- [Risk] 旧 dimension-only 页面行为回归 → Mitigation：保留兼容路径并用两种快照 fixture 做回归测试。
- [Risk] 分片字段未来变化或不再互斥完备 → Mitigation：每层校验父子总数守恒，不守恒即停止并标记 `PARTIAL`。
- [Risk] 长任务续跑形成混合时点 → Mitigation：保留源端总数漂移证据；用于交付的快照从空目录开始，并验证累计 manifest 与 JSONL 唯一数一致。
- [Risk] 修复前快照已把类型名称保存为数字文本 → Mitigation：投影优先按保留的类型代码归一化；后续新快照由 mapper 直接输出中文类型名称。
- [Risk] 同一任务因不同审计记录在管理列表重复出现，或详情空数组被误作权威缺失 → Mitigation：按任务 ID 去重，并以任一来源的非空证据为准；真实正例、双任务例和空例共同验收。

## Migration Plan

先升级本机 OpenCLI 只读适配器并通过分页、短抓取、分片守恒、续跑累计和关系专属详情恢复测试；再从空目录执行 `opencli szdata tag-snapshot --scope all`，校验标签值、维度、详情和关联文件的唯一数及 manifest，最后生成新的双视图页面。旧快照和旧页面不覆盖；若新输入校验失败，原子发布逻辑保留旧有效投影。
